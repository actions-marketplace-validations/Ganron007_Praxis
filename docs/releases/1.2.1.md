# Praxis 1.2.1

This patch strengthens the boundaries around scanning, fixing, undoing, and CI gating.

## Fixes

- Restore the advertised Node 18 runtime compatibility by using `write-file-atomic` 5.
- Keep GitHub annotations and PR-comment diagnostics off CI JSON stdout, and escape workflow-command values.
- Enforce `--always-fail-on` before `--fail-on`, including accepted baseline findings. Dependency severities now participate in these gates.
- Report incomplete agent and dependency audits as CI failures instead of passing with missing results. CI JSON includes `scanComplete`, `dependencyAudit`, and `floorPass`.
- Forward `--deep` through both CI command spellings and the Marketplace runner.
- Run the CLI and locked dependencies from the selected GitHub Action ref. Every composite output is mapped to the scan step.
- Apply the net-new PR gate once, compare the same requested path in both refs, include all severities above its floor, retain the always-fail floor, and refuse missing or failed base scans. Base worktrees are removed after scanning.
- Treat Action inputs as argument data, and use the final gate decision consistently in summaries and PR comments.
- Validate fix paths against the project boundary and real symlink destinations. Protect Git metadata, scanner state, and existing companion files from overwrites.
- Revalidate an approved plan before writing, use atomic file writes, and restore all touched files if a later write fails. Failed verification attempts are restored before generating another plan; regenerated plans require approval unless an explicit automatic mode is enabled.
- Apply replacement text literally, including dollar-sign tokens, instead of interpreting JavaScript string-replacement syntax.
- Preserve the last valid plan when an editor returns an invalid plan.
- Preflight all undo edits, preserve later user changes, and retain failed and unattempted log entries. New fix records include content hashes and edit offsets so deletions and dependent edits can be undone correctly.
- Redact raw secret matches in both web report endpoints. Count only active scans against queue capacity, and close progress streams for finished jobs.
- Validate local web Host headers on read routes as well as write routes, reject loopback lookalike names, and require matching origins for browser mutations.
- Restrict automatic `GITHUB_TOKEN` injection to the actual `github.com` host.
- Require `--trust-plugins` before importing local scanner plugins. Remote and web scans never execute repository plugins; plugin code runs with the operator's permissions, without an in-process sandbox claim.
- Clear completed scanner timeout handles promptly.
- Update the scan playbook after scoring, avoiding a swallowed reference error that prevented history updates.
- Gate npm publishing on tests, lint, and determinism, and add a real Marketplace action smoke test to CI.
- Route file discovery through a shared helper that bounds glob pattern length, nesting, and expansion, and refuses directory symlink traversal.

## Known dependency advisory

The production dependency chain `fast-glob → micromatch → braces` remains affected by
[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
At review time, upstream lists no patched version. Praxis bounds patterns before
calling this dependency, including target-controlled ignore patterns. This is an
application mitigation; it does not remove the advisory from `npm audit`.

## CI behavior

An unavailable dependency audit now fails CI. Install the ecosystem's audit tool and
check registry connectivity, or select `--no-deps` / Action `deps: 'false'` explicitly.
Net-new comparison uses source finding identities (`file:rule`); dependency CVEs
remain part of scoring and explicit severity floors, rather than the source diff.

Undo reverses recorded file edits without changing unrelated files or the Git index.
If a file changed after a fix, review the changes before retrying; failed undo records
remain available. Multi-file writes are individually atomic with rollback on errors;
they are not a single filesystem transaction across a power loss or process kill.
